# GTAVive.asi source reconstruction notes

The GTA: Vive Alpha 0.1 script half (`GTAVive.asi`, linked 2016-05-26 with
VS2015, /MT) never had its source published. This project is a full
reconstruction from the binary, made with Ghidra 12.1.2
(headless decompilation of all 862 functions) plus targeted disassembly
(`dumpbin /disasm`) to recover float-register arguments Ghidra lost.

The reconstruction is **behavioral, not byte-identical**: it is clean,
portable C++ that makes the same native calls with the same argument values
in the same order as the original. That property is machine-verified (see
"Verification" below).

## Key constants (from .rdata @0x18003dXXX)

- world scale `1.075` (de44), origin height `1.1549990177154541` = 0x3F93D702 (de48)
- gun calibration rotX/rotY/rotZ = `-70 / -7.25 / -0.75` deg (de94+de30 folded sin/cos, de9c, de80+de3c)
- prop rotation offsets: GetRotation(`-81.25, 257, 264.25`) + (0, `56.5`, yawDelta) (dea4, de6c, de70, de5c)
- melee prop rotation: GetRotation(`127, 1.25, -0.75`) - these are the kx/ky/kz values the 'U' key writes to gravovrvalues.txt. **The alpha only ever WRITES that file; nothing reads it.**
- weapon hashes: pistol 0x1B06D571, microsmg 0x13532244, assaultshotgun 0xE284C527, rpg 0xB1CA77B1, knuckle 0xD8DF3C3C (grip)
- fire: pistol dmg 10 spread ±250*0.02; SMG dmg 4 spread ±500*0.02, cooldown 0.25 (-0.1/frame); shotgun 5 pellets dmg 15 spread ±2000*0.02; RPG dmg 10 via WEAPON_VEHICLE_ROCKET asset
- bullet speed for weapons 0-2 is `3212836864.0f` - the alpha stores -1.0f's bit pattern as an int and converts it (`BULLET_SPEED_QUIRK`); the RPG passes a true -1.0f
- walk redirection: nudge origin ±0.05/frame when the player leaves the projected play area; snap origin to player when >10 units out
- in-vehicle camera: bone 11816 anchor + 0.675 height offset, grip recenters

## Verification

1. **Import parity**: identical mangled imports - 8 ScriptHookV + 9 OVRInject
   + DirectInput8Create. (The original additionally imported
   ADVAPI32!SystemFunction036 via the VS2015 CRT; the VS2022 CRT doesn't.)
2. **Trace equivalence** (`Tests\TraceHarness\run_traces.ps1`): stub
   ScriptHookV/OVRInject DLLs log every nativeInit/Push/Call; the original
   and rebuilt .asi run 40 simulated frames across 7 scenarios (idle,
   vehicle+steering+grip-recenter, fire all 4 weapons + weapon cycling,
   teleport to world, teleport-carjack, melee, fly-move).
   Result: **29,578 trace lines, bit-identical** except two 1-ULP float
   rounding differences in the shotgun's random spread (VS2015 vs VS2022
   instruction scheduling; ~0.15mm of bullet deviation at 120m).

## Post-reconstruction changes

The mapping, constants and verification above describe the faithful
reconstruction baseline. Changes made on top of it:

- VR-mode entry / prop respawn moved from plain **L** to **Ctrl+L**
  (`IsCtrlHeld()` in keyboard.cpp, physical keyboard state). This was the
  first intentional behavior change from the alpha.
- Later additions are marked "not in the alpha" in `script.cpp` and
  `sdk/natives.h`: the `[Beta]` options read from `gtaovr\gtavive.ini`
  (movement, camera anchoring, vehicle/fall attitude follow, VR height,
  auto-start), VR off/on (Ctrl+Shift+L), re-centre view (Ctrl+Shift+C),
  the character-switch block, the "VR not ready" notification and the
  diagnostic trace (`gtavive_trace.txt`).

## Known deliberate deviations

- The 2 ULP shotgun-spread roundings above.
- The original read three uninitialized stack floats as the initial
  "previous hand position" for melee; the reconstruction zero-initializes
  them (first-frame-only difference, and only while grip is held).
- The joystick pointer array is bounds-checked at 16 (the original wrote
  past its 16-slot array if >16 joysticks were attached).
- `rand()` seeding/sequence matches MSVC's unseeded default in both.

## Porting notes

- The .asi half is renderer-agnostic: it talks to the game only through
  ScriptHookV natives and to VR only through OVRInject's exported
  HMDSupport/TrackedController API plus inline header accessors. A port to
  another renderer replaces OVRInject's D3D11 hooking/mirroring internals; keep the
  HMDSupport public surface (or port both halves together and break ABI
  freely, since both are now source).
- `sdk/natives.h` uses the original 2015-era native hashes; ScriptHookV
  translates them across game versions, so they remain valid on newer
  ScriptHookV builds.
